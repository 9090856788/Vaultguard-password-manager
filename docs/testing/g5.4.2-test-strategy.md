# G5.4.2 VaultItem Encryption Test Strategy

**Status:** Planning only; no tests are authorized by this document

## 1. Test Layers

### Crypto contract tests

Use the existing G5.3 test foundation and test the integration boundary with
fixed synthetic keys and non-secret fixtures:

- encrypt/decrypt a valid field envelope;
- reject wrong VEK, vault ID, item ID, field, revision, key ID, purpose,
  version, algorithm, ciphertext, tag, nonce, or AAD;
- reject unsupported and malformed envelopes;
- verify fresh nonces and canonical length-delimited AAD;
- verify exact 32-byte VEK requirements;
- ensure no test output prints plaintext or key material.

### Lifecycle and repository tests

- preparation allocates a server-side ObjectId and persists `preparing`;
- preparation persists metadata only;
- valid finalize transitions `preparing` to `active` atomically;
- arbitrary/unprepared IDs are rejected;
- owner, vault, and category scoping rejects IDOR and cross-resource access;
- active reads and lists exclude preparing/deleted records as specified;
- metadata update increments revision with CAS;
- encrypted-secret update authenticates the resulting revision;
- delete increments revision and excludes the item;
- restore requires CAS and restores only the lifecycle state;
- no last-write-wins behavior exists.

### HTTP/API tests

Use the repository's approved Supertest/API infrastructure when available.
Verify authentication, exact status codes, `If-Match`, safe response shapes,
request IDs, generic error responses, unknown-field rejection, and no direct
controller-to-MongoDB access. Include both valid and malformed JSON bodies.

### Validation tests

For each endpoint reject:

- plaintext `password`, `username`, `notes`, `totp`, `recoveryCodes`, `secret`;
- `masterPassword`, `vaultMasterPassword`, `kek`, and `vek`;
- unknown top-level and nested fields;
- oversized title, URL, tags, field count, ciphertext, and request body;
- malformed base64url, nonce, tag, AAD, key ID, version, and algorithm;
- client-supplied owner IDs or unsupported lifecycle fields.

Every rejection assertion must verify that the submitted secret value is absent
from the response body, thrown error, structured event, and captured log.

### Concurrency and replay tests

- two updates with the same revision permit one winner;
- the loser receives `412`;
- exact retry returns the documented replay response;
- divergent retry returns conflict;
- concurrent delete/update cannot resurrect or overwrite unexpectedly;
- preparation/finalization races preserve one lifecycle transition.

### Security regression tests

- no plaintext secret field appears in Mongoose documents or repository update
  objects;
- no raw VEK/KEK/master password reaches controller, service, repository, or
  logger arguments;
- activity/audit records contain only safe metadata and reason codes;
- `VAULT_ENCRYPTION_NOT_READY` remains unchanged for legacy endpoints;
- no crypto primitive is duplicated or altered;
- existing G5.1, G5.2, G5.3, and G5.4.1 tests remain green.

## 2. Integration Evidence

Unit tests with repository doubles are necessary but insufficient. Before the
G5.4.2 security gate, add MongoDB-backed integration coverage if the approved
test infrastructure permits it, or record the explicit environment blocker.
Verify actual compound indexes, strict Mongoose validation, atomic updates,
projection behavior, and TTL/cleanup behavior for preparation records.

## 3. Required Test Commands

At implementation time run at minimum:

```text
npm test
npm run lint
npm run build
git diff --check
```

The implementation report must include exact test counts, skipped/deferred
tests, changed files, and evidence that no unrelated scope was included.

## 4. Acceptance Gate

G5.4.2 fails if any test demonstrates plaintext secret acceptance or leakage,
raw-key handling, cross-owner/cross-vault access, arbitrary item-ID
finalization, AAD mismatch acceptance, stale overwrite, unsupported-version
acceptance, unsafe error disclosure, or lifecycle bypass. A failing P0/P1
security or integrity test blocks commit and any next gate.
